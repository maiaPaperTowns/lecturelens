# `models/` — trained artifacts + registry

This directory is the **model registry**. `app/ml/registry.py` reads it at runtime.

```
models/
  embeddings/
    embedder.joblib            # TF-IDF + Truncated SVD text encoder
  concept_classifier/
    metadata.json              # every version, its metrics, and which is `active`
    sklearn_gradient_boosting.joblib
    pytorch_mlp.pt             # + pytorch_mlp.json sidecar
  difficulty/
    metadata.json
    sklearn_gradient_boosting.joblib
    pytorch_mlp.pt
  evaluation_report.json       # written by scripts/evaluate_models.py
```

## How artifacts get here

`backend/scripts/train_models.py` produces them. The backend Docker entrypoint
runs it automatically on first boot if `concept_classifier/metadata.json` is
missing. Until artifacts exist, the API transparently falls back to the
documented **heuristic** models (`heuristic-v1`) so nothing breaks.

## `metadata.json` schema

```json
{
  "name": "concept_classifier",
  "active": "pytorch-mlp-v1",
  "versions": {
    "sklearn-gradient_boosting": {
      "family": "sklearn",
      "artifact": "sklearn_gradient_boosting.joblib",
      "trained_at": "2026-01-01T12:00:00",
      "metrics": { "accuracy": 0.87, "f1_macro": 0.86, "confusion_matrix": [[...]] },
      "use_embeddings": true
    },
    "pytorch-mlp-v1": { "family": "pytorch", "artifact": "pytorch_mlp.pt", "...": "..." }
  }
}
```

## Version control

Binary artifacts (`*.joblib`, `*.pt`, `*.bin`) are **git-ignored** — they are
regenerated by `train_models.py`. Only this README and `metadata.json` files are
meant to be committed (and even those are optional).
